# Nexo UPA 2026 · Fase 0: auditoría y mapa de funciones

Fecha: 29 de septiembre de 2026. Rama de trabajo: `redesign-2026`. Esta auditoría describe el código existente; no convierte una simulación local en un servicio compartido. El encargo actual amplía el alcance de la documentación histórica de `design/`: se conservarán las funciones actuales y se diseñarán las nuevas por fases, con modo claro y oscuro.

## Producto y arquitectura encontrados

- Nexo UPA es una demo social web/PWA para la comunidad de la Universidad Politécnica de Atlautla, no una app oficial. La entrada estática de GitHub Pages es React 19 + TypeScript + Vite; también existe una ruta de desarrollo Vinext/Next. El diseño actual es blanco/verde, de prioridad móvil, con navegación lateral en escritorio y barra inferior en móvil.
- La aplicación está concentrada en una página y cinco vistas (`inicio`, `explorar`, `notificaciones`, `chats`, `perfil`), más detalle de publicación, compositor, visor de Dump y diálogos. `mercado` figura en el tipo `View`, pero hoy es una pestaña de Explorar, no una ruta independiente.
- Las publicaciones, seguidores, mensajes, perfil, borrador, cupos y notificaciones de demostración se guardan en un único registro IndexedDB (`nexo-upa-demo`). Los perfiles ajenos, la actividad entrante y las fotografías de UPA son ejemplos. No hay una base social multiusuario ni sincronización entre equipos.
- `local-server/server.mjs` es una API local de cuentas con SQLite, separada de la web pública. Los enlaces de **Iniciar sesión** y **Crear cuenta** están presentes, pero sus URL en `lib/app-config.ts` siguen vacías a la espera del login del usuario. La demo pública no recibe ni guarda contraseñas.

## Debilidades principales y orden de intervención

1. **Cámara y medios**: el nombre “Dump” sugiere una captura social rápida, pero solo existe un selector de archivos dentro de un modal. No hay preview de cámara, gesto de captura, zoom ni edición. Es el vacío visual y funcional P0 más visible.
2. **Rendimiento estructural**: el build estático actual entrega un único JavaScript de 443,939 B (136.41 kB gzip) y un CSS de 178,995 B (27.78 kB gzip). Todas las vistas se importan al inicio; feed, Explorar, perfil, alertas y mensajes renderizan listas completas sin cursores ni virtualización. No se ha medido TTI, 60 fps, memoria ni latencia gestual en teléfono real; el tamaño del bundle no demuestra esos objetivos.
3. **Fidelidad social y confianza**: presencia, mensajes entrantes, actividad y cupos son locales. No existen moderación, bloqueo, denuncias de abuso, privacidad de cuenta ni sincronización. El “Reporte” de objeto perdido **no** es una denuncia de contenido.
4. **Sistema visual**: tokens blanco/verde, medidas táctiles y reducción de movimiento existen, pero falta modo oscuro real; elementos interactivos, vacíos y superficies de medios no comparten un contrato completo de estados/motion.
5. **Persistencia de medios**: los archivos completos se convierten a Data URL y se guardan en el mismo registro IndexedDB. No hay variantes de imagen, placeholder, progreso de subida, caché con límites ni rollback ante fallo de guardado.

## Contrato de datos y límites antes de nuevas funciones

No se implementará como “funcionando” ninguna función que dependa de un servidor ausente. La futura red compartida requiere, al menos, cuentas/sesiones verificadas y autorización, perfiles, relaciones de seguimiento, posts y medios, reacciones, reposts, comentarios, stories con expiración de servidor, conversaciones/mensajes/adjuntos con expiración, notificaciones, cupos diarios de Notify/Reporte, denuncias/moderación y estados de bloqueo/restricción. Los endpoints/tablas exactos se definirán en el análisis de brechas **antes** de construir cada función dependiente. Se conservará la API local de cuentas como prototipo aislado, no se conectará automáticamente con el login externo del usuario.

## Regresión obligatoria para cualquier fase posterior

Probar en modo claro y oscuro cuando exista; 360 px, tableta y escritorio; teclado/lector y reducción de movimiento. Mantener explícitos los estados de demo local durante toda la transición.
